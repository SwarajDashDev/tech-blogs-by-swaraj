SWR in React Native: A Lightweight Alternative to React Query

📅 2026-08-01
Explore how SWR can simplify data fetching in React Native apps, offering a tiny footprint and built‑in caching without the ceremony of React Query.
react native swr data fetching

Insight

SWR (stale‑while‑revalidate) brings a minimal‑API data layer to React Native. Unlike React Query, it has no explicit mutation helpers and relies on the native fetch API, making the bundle size ~2 KB gzipped. Its hook‑first design works seamlessly with Expo and the Hermes engine, and the built‑in cache lives in memory, automatically revalidating on focus or network reconnection. For simple list screens or occasional detail fetches, SWR eliminates the boilerplate of query keys, stale times, and manual invalidation.

Example

import useSWR from "swr"
import { Text, View, ActivityIndicator } from "react-native"

const fetcher = (url: string) => fetch(url).then(r => r.json())

export default function UserProfile({ userId }: { userId: string }) {
  const { data, error, isLoading } = useSWR(`/api/users/${userId}`, fetcher)

  if (isLoading) return <ActivityIndicator />
  if (error) return <Text>Failed to load</Text>

  return (
    <View>
      <Text>{data.name}</Text>
      <Text>{data.email}</Text>
    </View>
  )
}

Takeaway

When your app only needs straightforward GET requests with automatic caching and revalidation, SWR gives you a tiny, zero‑config solution. Reserve heavier tools like React Query for complex mutation flows or shared cache across many screens.

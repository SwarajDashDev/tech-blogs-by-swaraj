Dynamic Screen Code‑Splitting in React Native

📅 2026-08-01
Learn how to lazily load heavyweight screens with React.lazy and dynamic import to shrink the initial bundle and speed up app startup.
react native performance code splitting

Insight

Metro bundles the entire JavaScript payload by default, which can bloat the initial load time, especially when you have a few screens packed with heavy UI libraries or large assets. By leveraging React.lazy and dynamic import(), you can defer loading of those screens until the user actually navigates to them. This screen‑level code‑splitting keeps the start‑up bundle lean while still preserving the native navigation experience.

Example

import React, { Suspense } from 'react';
import { NavigationContainer } from '@react-navigation/native';
import { createStackNavigator } from '@react-navigation/stack';

const HomeScreen = React.lazy(() => import('../screens/HomeScreen'));
const SettingsScreen = React.lazy(() => import('../screens/SettingsScreen'));

const Stack = createStackNavigator();

export default function App() {
  return (
    <NavigationContainer>
      <Suspense fallback={null}>
        <Stack.Navigator initialRouteName="Home">
          <Stack.Screen name="Home" component={HomeScreen} />
          <Stack.Screen name="Settings" component={SettingsScreen} />
        </Stack.Navigator>
      </Suspense>
    </NavigationContainer>
  );
}

Takeaway

Only apply lazy loading to screens that noticeably increase bundle size (e.g., those pulling in chart libraries or large image sets). Keep navigation definitions static so Metro can still pre‑fetch the routes, and always test on a physical device to verify the perceived startup improvement.

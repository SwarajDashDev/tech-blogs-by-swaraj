Why SWR Can Be a Lightweight Alternative to React Query in React Native

📅 2026-09-18
Explore how SWR offers a minimalistic, cache‑first data fetching experience for React Native, and when it makes sense over React Query.
react native swr data fetching

Insight

SWR (stale‑while‑revalidate) brings a tiny API surface and automatic caching to React Native without the boilerplate of React Query. It shines when you need simple GET requests, optimistic UI updates are unnecessary, and you prefer a hook‑only solution that works out‑of‑the‑box with fetch. Unlike React Query, SWR doesn’t ship with mutation helpers, pagination utilities, or background refetch intervals, which keeps the bundle size low and the learning curve shallow. For apps that primarily display read‑only lists or detail screens, SWR can reduce code churn while still giving you stale‑while‑revalidate semantics.

Example

import useSWR from 'swr';

const fetcher = (url: string) => fetch(url).then(r => r.json());

export function UserList() {
  const { data, error, isLoading } = useSWR('/api/users', fetcher);

  if (isLoading) return <ActivityIndicator />;
  if (error) return <Text>Failed to load</Text>;

  return (
    <FlatList
      data={data}
      keyExtractor={item => item.id}
      renderItem={({ item }) => <Text>{item.name}</Text>}
    />
  );
}

Takeaway

When your data needs are read‑heavy and you want a zero‑config, tiny dependency, reach for SWR. Reserve React Query for complex mutation flows, pagination, or when you need fine‑grained cache control.

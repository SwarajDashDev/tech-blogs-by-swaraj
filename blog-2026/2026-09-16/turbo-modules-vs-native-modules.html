TurboModules vs Native Modules: Picking the Right Bridge for Performance

📅 2026-09-16
Understand when to use React Native TurboModules instead of classic Native Modules and how they impact startup time and runtime performance.
react native performance native modules

Insight

TurboModules are the next‑generation bridge introduced in RN 0.71. Unlike classic Native Modules, they are lazily loaded and communicate with JavaScript via JSI, eliminating the costly JSON serialization step. This reduces app startup time and enables near‑native call latency, especially for frequently used APIs like sensor data or cryptography. However, TurboModules require a C++‑backed implementation and are only supported on iOS 15+ and Android API 21+. For simple, infrequently used native code, classic Native Modules remain the pragmatic choice because they need only Java/Kotlin or Objective‑C/Swift and work across all OS versions.

Example

// src/native/DeviceInfoTurbo.ts
import {TurboModuleRegistry} from 'react-native';
const DeviceInfo = TurboModuleRegistry.getEnforcing('DeviceInfo');
export const getBatteryLevel = async () => {
  const level = await DeviceInfo.getBatteryLevel();
  return level;
};

The same API as a classic module would look like NativeModules.DeviceInfo.getBatteryLevel() with a promise wrapper.

Takeaway

Start new native bridges as TurboModules only when the API is performance‑critical or called often. Keep legacy or low‑frequency code in classic Native Modules to avoid extra build complexity and maintain broader device compatibility.

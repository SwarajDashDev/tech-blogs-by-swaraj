Branded Types: Safer IDs in React Native TypeScript

📅 2026-07-31
Use TypeScript branded types to prevent mixing up identifier strings across your React Native app, catching bugs at compile time.
typescript react-native type-safety

Insight

In many mobile apps, IDs (userId, postId, etc.) are just strings at runtime, but mixing them up can cause subtle bugs—especially when they travel through navigation params or API payloads. TypeScript's branding technique creates nominal types without runtime overhead, letting the compiler enforce that a UserId never gets passed where a PostId is expected.

Example

// brand.ts
export type Brand<K, T> = K & { __brand: T };
export type UserId = Brand<string, "UserId">;
export type PostId = Brand<string, "PostId">;

// usage.ts
function fetchUser(id: UserId) { /* ... */ }
function fetchPost(id: PostId) { /* ... */ }

const uid = "abc123" as UserId; // OK
const pid = "def456" as PostId; // OK
// fetchUser(pid); // ❌ TypeScript error

Takeaway

Introduce branded ID types in a shared types folder and cast only at the API boundary. This adds zero runtime cost while giving you compile‑time confidence that IDs are never swapped.

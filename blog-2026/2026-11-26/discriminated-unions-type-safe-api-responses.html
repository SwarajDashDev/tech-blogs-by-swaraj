Discriminated Unions: Type‑Safe API Responses in React Native

📅 2026-11-26
Learn how TypeScript discriminated unions can make handling varied API responses safer and clearer in React Native apps.
typescript react native api

Insight

When consuming REST endpoints, responses often come in multiple shapes—success payloads, validation errors, or server failures. Using TypeScript's discriminated unions lets you model these variants explicitly, so the compiler forces you to handle each case. This reduces runtime crashes caused by unexpected null or missing fields and makes the intent of your data flow obvious to teammates.

Example

// Define the possible response shapes
type Success = { status: 'ok'; data: User };
type ValidationError = { status: 'error'; code: 400; errors: Record<string, string> };
type ServerError = { status: 'error'; code: 500; message: string };

type ApiResponse = Success | ValidationError | ServerError;

async function fetchUser(id: string): Promise<ApiResponse> {
  const res = await fetch(`https://api.example.com/users/${id}`);
  return res.json();
}

// Consumer with exhaustive checking
async function showUser(id: string) {
  const resp = await fetchUser(id);
  if (resp.status === 'ok') {
    console.log('User:', resp.data);
  } else if (resp.code === 400) {
    console.warn('Validation errors:', resp.errors);
  } else {
    console.error('Server error:', resp.message);
  }
}

Takeaway

Model API responses with a discriminated union and a common status field. The TypeScript compiler will then guide you to handle every branch, turning ambiguous any payloads into a predictable, type‑safe flow.

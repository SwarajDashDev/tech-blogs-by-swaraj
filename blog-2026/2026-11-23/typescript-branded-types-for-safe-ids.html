TypeScript Branded Types: Safer IDs in React Native

📅 2026-11-23
Use TypeScript's branded types to prevent accidental mixing of different ID strings, improving runtime safety without runtime overhead.
typescript react-native best-practices

Insight

In many mobile apps, IDs from different domains (e.g., userId, orderId) are just plain strings. A typo or copy‑paste error can silently pass the wrong ID to an API, leading to hard‑to‑track bugs. TypeScript's branded types let you create distinct compile‑time types for each ID while keeping the runtime representation unchanged. This adds zero runtime cost but gives the compiler a chance to catch mismatches early.

Example

// Define branded types
type Brand<K, T> = K & { __brand: T };
export type UserId = Brand<string, 'UserId'>;
export type OrderId = Brand<string, 'OrderId'>;

// Helper factories
const userId = (id: string): UserId => id as UserId;
const orderId = (id: string): OrderId => id as OrderId;

// Usage
function fetchUser(id: UserId) { /* ... */ }
function fetchOrder(id: OrderId) { /* ... */ }

// Compiler error – mismatched ID
fetchUser(orderId('123')); // ❌ Type 'OrderId' is not assignable to type 'UserId'

Takeaway

Wrap raw strings in branded types wherever you expose IDs across layers. The extra type safety prevents accidental cross‑contamination and makes refactoring safer, all without affecting bundle size or performance.

Monorepo Magic: Sharing Code Between React Native and Next.js with Turborepo

📅 2026-10-15
Learn how a Turborepo monorepo can streamline shared UI components and utilities across React Native and Next.js, reducing duplication and keeping type safety intact.
monorepo turborepo react-native

Insight

A Turborepo monorepo lets you keep a single source of truth for UI components, hooks, and type definitions that run on both React Native and Next.js. By configuring a shared ui package with platform‑specific entry points (index.native.tsx vs index.web.tsx), you avoid copy‑pasting code and benefit from unified linting, testing, and TypeScript checks. The key is to let the bundler resolve the correct file based on the target platform, while Turborepo caches builds for lightning‑fast CI.

Example

// packages/ui/src/Button.tsx (common API)
export const Button = ({title, onPress}: {title: string; onPress: () => void}) => {
  return Platform.OS === 'web' ? (
    <button onClick={onPress}>{title}</button>
  ) : (
    <TouchableOpacity onPress={onPress} style={styles.btn}>
      <Text>{title}</Text>
    </TouchableOpacity>
  );
};

// packages/ui/index.native.tsx
export * from './src/Button';

// packages/ui/index.web.tsx
export * from './src/Button';

Now both apps import the same component:

import {Button} from '@myorg/ui';

Takeaway

Set up a Turborepo with a ui package and platform‑specific entry files. This pattern cuts duplication, guarantees type safety across platforms, and leverages Turborepo's caching for faster builds.

Stable Callbacks: How `useCallback` Can Prevent Unnecessary Re‑renders in React Native

📅 2026-08-18
A quick look at why memoizing callbacks with `useCallback` matters in RN and how a tiny pattern can keep your UI snappy.
performance react-native hooks

Insight

In React Native, passing a freshly created function to a child component forces that child to re‑render, even if its props haven't otherwise changed. This hidden cost shows up most often in list items or animated components where the render budget is tight. By wrapping the handler in useCallback with a stable dependency list, you give React a reference it can compare, cutting the needless renders and preserving frame rates.

Example

import { useCallback } from 'react';
import { TouchableOpacity, Text } from 'react-native';

function ListItem({ id, onSelect }: { id: string; onSelect: (id: string) => void }) {
  const handlePress = useCallback(() => onSelect(id), [onSelect, id]);
  return (
    <TouchableOpacity onPress={handlePress}>
      <Text>{id}</Text>
    </TouchableOpacity>
  );
}

Notice that handlePress retains the same reference across renders unless onSelect or id actually change.

Takeaway

Whenever you pass a function down the tree, wrap it in useCallback with the minimal dependency set. It’s a one‑line guard that can shave milliseconds off render cycles, especially in large FlatLists or animated screens.

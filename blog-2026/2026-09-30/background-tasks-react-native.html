Background Tasks in React Native: Choosing the Right Tool

📅 2026-09-30
A quick look at how to run periodic work in React Native using Expo Task Manager vs react-native-background-fetch, and when each makes sense.
react native background expo

Insight

Running code when the app is in the background is a common need—think location polling, analytics, or silent push handling. Expo provides TaskManager out‑of‑the‑box, but it only works inside the Expo managed workflow. For bare or ejected projects, react-native-background-fetch offers a native module that survives app termination on both iOS and Android, but it requires extra native setup and careful permission handling. Choose TaskManager for quick prototypes or when you stay within Expo; switch to background‑fetch when you need fine‑grained control, custom native code, or a truly detached build.

Example

// expo-task-manager.ts
import * as TaskManager from 'expo-task-manager';
import * as BackgroundFetch from 'expo-background-fetch';

const TASK_NAME = 'fetch-data';

TaskManager.defineTask(TASK_NAME, async () => {
  // Your periodic logic here
  await fetch('https://api.example.com/sync');
  return BackgroundFetch.Result.NewData;
});

await BackgroundFetch.registerTaskAsync(TASK_NAME, {
  minimumInterval: 15 * 60, // 15 minutes
  stopOnTerminate: false,
});

Takeaway

Start with Expo's TaskManager for speed, but migrate to react-native-background-fetch when you need native reliability or a detached workflow. Keep the task lightweight—heavy work should be offloaded to a server to avoid draining battery.
